# S1 — Tag exclusion (`govibe_dev`)

Scratch copy: `spikes/s1` (from `spikes/base`, which is the repo at commit a353f8a minus `.git`, bolt files, `tmp/`, the binary).
Go 1.26.5 darwin/arm64. Binaries built with `-trimpath -ldflags='-s -w'`.

## What was changed in the copy (throwaway prototype)
- `routes/devmount_dev.go` (`//go:build govibe_dev`, 134 lines): everything that followed the Hello routes in
  `NewRouter` (`/dev/docs`, graph store, db explorer, indexer, MCP, the async index run), as `mountDev(r chi.Router)`.
- `routes/devmount_nodev.go` (`//go:build !govibe_dev`, 8 lines): `func mountDev(r chi.Router) {}`.
- `routes/routes.go`: 180 -> 62 lines, one call `mountDev(r)`; dev imports removed.
- `controllers/dev*.go` (9 files incl. 3 test files): `//go:build govibe_dev` added at the top. **This was necessary**:
  they share package `controllers` with `Home`/`HelloAPI`/`Hello`, so as long as they were untagged the default
  build still linked goldmark, chroma, codegraph, dbexplorer, graphdb (via `routes` -> `controllers`).

## Measurements
| | Baseline (today) | Default build (no tag) | Tagged (`-tags govibe_dev`) |
| --- | --- | --- | --- |
| `go list -deps .` packages | 440 | **240** | 440 (identical to today) |
| of which standard library | 233 | 202 | 233 |
| of which non-std (third party + this module) | 207 | 38 (27 third party + 11 module) | 207 (192 third party + 15 module) |
| binary size | 30,049,762 B | **8,922,626 B (8.5 MiB)** | 30,049,794 B (28.7 MiB) |
| cold-cache `go build` wall time* | n/m | 20 s | 28 s |

\* Cold `GOCACHE` under the scratch dir, but the machine was at load average ~70-100 from other forks; treat as
order-of-magnitude only (default is clearly cheaper, not "28 vs 20" precisely).

Default build is **200 packages and 21.1 MB smaller** (-70% size, -45% packages). The tagged binary is byte-for-byte
the same size as today's (30,049,794 vs 30,049,762 B), so the move is behavior-preserving.

(a) **Forbidden packages in the default build: 0** of cayley (was 28), modelcontextprotocol (10), golang.org/x/tools
(19), goldmark (10), chroma (4). In the tagged build all five are present with exactly today's counts.
Whole dev-only set = 200 packages: 4 module packages (`business/services/codegraph`, `devmcp`, `storage/dbexplorer`,
`storage/graphdb`), 31 std packages, and 165 third party. Largest groups: x/tools 19, cayley 18, x/text 10, MCP SDK 10,
quad 10, goldmark 9, segmentio/asm 9, goja 5, chroma 4, prometheus (client_golang/common/procfs/client_model) 10,
hidalgo 3, gogo/protobuf 3, oauth2 2, jsonschema-go, uritemplate, httprouter, ...

What the default build still contains (the production set): chi, templ runtime, yaml.v3, logrus, mysql driver, sqlx,
goose (+ its mfridman/interpolate, sethvargo/go-retry, multierr, errgroup), and **workos-go/v10 (+ go-querystring,
uuid)** — the dead WorkOS client in `main.go`; T1.5 removes it, which will shave a few more packages and ~hundreds of KB.

(d) Runtime behavior (APP_ENV=dev unless stated, PORT=18091, scratch copy, `MARIADB_DSN`/`WORKOS_*` unset):
- Tagged binary: `/` 200, `/api/hello` 200, `/hello` 200, `/dev/docs/app` 200, `/dev/docs/specs` 200, `/dev/graph` 200,
  `/dev/graph/data/status` 200, `/dev/graph/reports` 200, `/assets/static/graph.js` 200,
  `POST /dev/mcp` with an `initialize` request returns an SSE `message` with the server capabilities and the
  graph_schema instructions; `GET /dev/mcp` is 405 (streamable HTTP, expected). The indexer ran all layers
  (`code` 6755 quads ... `done`, 10,800 quads, ~1.6 s). Without a DSN `/dev/db` is 404 and the log says
  "db explorer: no MARIADB_DSN configured, /dev/db disabled" (as today).
- Default binary, APP_ENV=dev **and** APP_ENV=prod: `/`, `/api/hello`, `/hello` 200; `/dev/docs/app`, `/dev/graph`,
  `/dev/db`, `/dev/mcp` all **404**. The dev routes are simply absent.

(e) What else drags dev code into the default build, i.e. the real Phase 2 work:
1. **`controllers/dev*.go` share a package with the app's controllers.** The compiler cannot exclude half a package by
   import; I had to tag 9 files. In the real design they move to `internal/devtools/devui`, imported only from the
   tagged kernel file. No tags inside the dev packages are needed then (and none are wanted, see "Tests" below).
2. **`routes` is the only importer of the dev stack** besides `controllers`; after the split nothing else in the default
   import graph reaches `codegraph`, `devmcp`, `dbexplorer`, `graphdb`. `cmd/govibe` does import them, which is correct
   (it is the tool, not the app binary).
3. **Embedded dev bytes are still in the default binary.** `assets.FS` embeds `static/**`, which includes dev-only
   `graph.js` 40 KB, `graph.css` 12 KB, `docs.css` 8 KB and `vendor/cytoscape.min.js` 428 KB (~490 KB of the 8.9 MB).
   They are not packages, so `go list -deps` does not show them; **A7's "no dev packages" check passes while dev
   JS/CSS still ships and is served at `/assets/static/graph.js` (200 in the default prod binary).** T1.4 (framework-owned
   dev FS behind the tag, served at `/_govibe/static`) is what removes this. A7 should also assert that
   `/assets/static/graph.js` is 404 in the default build.
4. **The Hello page links to the dev panel in the default build**: `home.templ` has 11 `/dev/*` hrefs to 4 distinct targets (`/dev/docs/app`,
   `/dev/docs/specs`, `/dev/graph`, `/dev/db`); the default prod binary's `/` serves all four, all 404.
   Confirms the need for `web.IfDev` (T1.4) and the A7 "no `/dev` link in `/`" assertion.
5. **`config.Config.Dev.*` and `middleware.DevNoCache`** are tiny, untagged and stay (not packages worth tagging).
6. **A forgotten tag is silent**: the default binary logs nothing about `/dev`. The spec's "one boot log line" is needed
   (it is not in this prototype).

## Tests under the tag (surprise)
`go test ./...` **without the tag fails to compile** `business/services/codegraph` tests:
`routes_chi_test.go` imports `controllers.DevDocsAppIndex`, `DevDBMeta`, `DevGraphReindex`, ... to build a real chi router
for the routes-layer tests. With dev files tagged in `controllers`, those symbols vanish. With the tag all tests pass
**except one**: `TestCallsLayerOnThisRepository` fails (`DevGraphReindex -> Indexer.Run missing`), because the calls
layer runs `packages.Load(cfg, "./...")` **without build tags**, so tagged files are invisible to it. This is the exact
problem T3.7 names ("tag-aware load") — now confirmed with a failing test — and it is also S3's central question.
Everything else: default `go test ./...` passes for `cmd/govibe`, `devmcp`, `storage/dbexplorer`, `storage/graphdb`;
`go test -tags govibe_dev ./controllers ./routes ./devmcp ./cmd/...` pass.
Consequences: (1) tag **only the kernel's import file**, not the dev packages, so `go test ./...` and `go vet ./...`
stay tag-free and complete; (2) `routes_chi_test.go` (a codegraph test importing controllers) must move or use devui
types when the controllers move; (3) the calls layer needs `BuildFlags: -tags govibe_dev` for the app's tagged files.

## Environment hazard found (not a spec issue, but important for every spike)
The developer's shell exports `MARIADB_DSN` (local `govibe` database on 127.0.0.1:3306) and `WORKOS_API_KEY` /
`WORKOS_CLIENT_ID`. My first runs of both binaries (before I noticed) connected to it: the default binary logged
"database connected and migrated" (goose: "no migrations to run. current version: 1", i.e. a no-op) and the tagged
binary opened the explorer with mutations off and read the schema for the `db` layer. Nothing was written. All later
runs used `unset MARIADB_DSN WORKOS_API_KEY WORKOS_CLIENT_ID`. Any spike that **boots an app** (default or tagged) **must unset those**. `go test` is safe: the DB tests read
`GOVIBE_TEST_MARIADB_DSN`, a different variable, and skip without it.
Also: the spec's A1 says `/dev/db` works "with a DSN", which this environment would always have; CI must not.

## Consequence for the design
The plan holds and is better than expected: tag exclusion works with a one-line call site and a no-op twin, the default
binary drops from 440 to 240 packages (200 fewer, 0 forbidden) and from 28.7 to 8.5 MiB, the tagged binary is
unchanged, and runtime behavior is as specified (404 for `/dev/*` in the default build in any APP_ENV). Updates to the
spec: (a) state the measured numbers (440 -> 240 packages, 30.0 -> 8.9 MB); (b) A7 must also cover embedded dev
assets (`/assets/static/graph.js` must be 404, and the app's `assets.FS` must not contain dev files) because package
counting alone passes while 490 KB of dev JS/CSS still ships; (c) tag the kernel's import file only, never the dev
packages (tagged files inside a shared package broke `go test ./...` for codegraph and hid code from the calls layer);
(d) T3.7 is not optional: the calls layer must load with `-tags govibe_dev`, shown by a real failing test;
(e) the A2 acceptance line ("`go list -deps ./...` of the app, default build, contains none of cayley/MCP/x/tools/goldmark/chroma")
is satisfied by exactly this mechanism, but note x/tools etc. remain in the app's `go.mod`/`go.sum` (already in Risks).
