# S6 — Offline facts: `inspect --json`

Scratch: `spikes/fw` (`govibe.Run` handles `serve`, `routes`, `inspect --json`, the app's own commands; `internal/routeinfo` is the
chi walk + `FuncForPC` extracted from the indexer so the app binary can use it without linking the graph code), `spikes/app`.
Offline consumer: `spikes/fw/cmd/spikeindex` feeds the document to the indexer through the new exported `Options.RouteSource`.
All app runs under `env -i`.

## What `inspect --json` does and does not do (checked)
| Requirement | Result |
| --- | --- |
| runs with an **empty environment** (`env -i ./shop inspect --json`) | Works, exit 0, one JSON document on stdout, 22.7 KB for 17 routes + 1 command and 6 build-info modules (a real app has dozens of modules: estimate a few KB more) |
| **no database**: a bogus `MARIADB_DSN` in the environment is ignored | Works (`OpenDB: false` on this path; `serve` and the app's commands use `OpenDB: true`) |
| **no dev mount, no indexer, no scheduler**, including in a **`-tags govibe_dev` build** | Works: the kernel mounts nothing under `/dev` (`build.tags` says `govibe_dev`). The tagged binary lists **18** routes, the 17 plus `GET /dev/app`, which is the **app's own** tag-only route (`routes/dev_on.go`, `mounted_by: app`), so a document taken from an untagged build misses the app's dev-only routes; `govibe graph index` should run `inspect` from a tagged build (the tag S3 also needs). It also shows a tension with the reserved-prefix rule: the spec reserves `/dev/*` for the panel but T7.3 (`App.DevTools`) wants apps to contribute dev pages, so the boot check must exempt tagged app dev routes or v1 must keep them out; the spike left the check a stub |
| time | median 13 ms (default build), 15 ms (tagged), max 19 ms over 20 runs, includes process start |
| `routes` (text table) | Same data, `METHOD path symbol` |
| registration tolerates a nil `rt.DB` | Yes: `routes.Register` builds `orderstore.New(rt.DB)` with a nil pool; `routes.Console` likewise |

## The document (`govibe.inspect/1`), as settled
```json
{
  "schema": "govibe.inspect/1",
  "app":       { "name": "shop", "module": "example.com/shop",
                 "root_hint": { "symbol": "example.com/shop/routes.Register", "file": "<as compiled>", "line": 17 } },
  "framework": { "module": "petars-dev/govibe", "version": "v0.0.0" },
  "go": "go1.26.5",
  "build": { "trimpath": false, "tags": "govibe_dev",
             "modules": [ { "path": "github.com/go-chi/chi/v5", "version": "v5.1.0" },
                          { "path": "petars-dev/govibe", "version": "v0.0.0", "replace_dir": "../fw" } ] },
  "routes": [ { "method": "GET", "path": "/api/orders",
                "handler":    { "symbol": "example.com/shop/routes.Register.func1.ListOrders.1",
                                "file": "<as compiled>", "line": 24 },
                "mounted_by": "app",
                "middleware": [ { "symbol": "...", "file": "...", "line": 67 } ] } ],
  "commands": [ { "name": "orders:export", "short": "Export orders",
                  "handler": { "symbol": "example.com/shop/routes.Console.ExportOrders.func1", "file": "...", "line": 13 } } ]
}
```
Design points, each from a measurement:
- **No symbol-derived `origin` in the document.** The first draft had one; it said `app` for the inlined framework closure `web.Health`
  (S2). The consumer classifies from `file` + `build.modules` + `root_hint`. `mounted_by` is the one origin fact only the running app knows (route table
  snapshot taken before `App.Routes` runs).
- `app.root_hint` and `build.modules` exist because the file spellings differ across four build modes (S2); without them the consumer cannot place a handler.
- `build.tags` tells `govibe graph index` which tags to type-check with (S3).
- `schema` is versioned; the tool should refuse an unknown major.
- Commands: handler is the `Run` func (here a closure from `commands.ExportOrders`; file:line resolves it to the declaring function). `schedule` fields arrive in Phase 4.
- Not in the document, deliberately: config values, DB schema, anything resolved from the environment.

## Consuming it offline (the real S6 question)
`spikeindex -root <app> -inspect <doc> -store <scratch dir>` runs layers `code, routes, docs, findings` (and the rest at defaults) with
`RouteSource` reading the document. Today `routesLayer.build` returns *"no router is wired (offline run); routes left as they were"* for a CLI index, so the
rule `docs.route_undocumented` (needs `routes`, `docs`) is **not checked** in CI. With the document:
- the routes layer ran (253 quads, status ok) in all four build modes; 17 routes; 0 unresolved handlers; identical classification across the four builds (S2);
- **`docs.route_undocumented` ran and produced 8 findings** for the app's own routes (`/plain`, `/hello`, `/api/orders/{id}`, `/files/*`, `/fw/static`, `/fw/health`, `/fw/ping`,
  `/fw/version`), none for the three routes the app's `ARCHITECTURE.md` mentions (`/`, `/api/hello`, `/api/orders`), and **none for the 6 framework routes** (`/_govibe/*`,
  `/assets/*`) thanks to the `origin=framework` skip (S2);
- so the gate can run the route rule in CI, closing the previous spec's backlog item.

## Surprises
0. **Registration code logs to stderr during `inspect`** (the demo's `rt.Log.Info("routes registered")` printed on every run). stdout stayed pure JSON, but the kernel should set the logger to `warn` (or discard) for the read-only commands, and `doctor` should treat anything on stdout other than the document as a failure.
1. **The config layer reports `ok` with 0 quads on an app whose `env.yml` is in the root** (it reads `config/env.yml`): "ok, nothing" is how a missing input looks, so `config.undeclared`/
   `config.unused` would pass vacuously. T3.1's Profile must make a missing configured path a **not checked, with the reason**, not an empty `ok`. (Same for `templates` 0 quads and `mcp` 0 quads in the
   app: expected there, but the layer status does not say why.)
2. **Process start dominates**: 13 ms for the whole document, so running `inspect --json` per `govibe graph index`/`doctor` call is free. Building the app first is not: `go run` or `go build` cold is seconds
   (S3's cold numbers), so `govibe graph index` should build the app binary once and reuse it (cache keyed by `go.sum` + sources' mtimes), or fail with a clear "app does not build" finding.
3. `inspect` needs the framework to export the walk as a **light package**: `routeinfo` imports chi, reflect and runtime only. Had it stayed in the codegraph package, the default app binary would
   link cayley, x/tools and the MCP SDK just to print its routes (A2).
4. Method values, closures and inlined factories all produce symbols that are not declared functions (S2); the document ships them raw and the indexer's existing `resolveFunc`
   (file:line to declared function, `-fm` by symbol) handles them once the build root is known.

## Consequence for the design
The plan holds and is cheap: the app binary can print the route and command facts offline in about 13 ms, and the existing injectable `routeSource` is the right seam. Changes to carry:
(a) export the route-source option (`Options.RouteSource`, T3.6) **and** `BuildRoot`/`Modules`/`FrameworkModule`, filled from the document; (b) the document carries `root_hint`, `build.{trimpath,tags,modules}`,
`mounted_by`, and no symbol-derived origin; (c) `internal/routeinfo` (light) is a new package in the layout, used by `kernel`/`inspect` and by `codegraph`; (d) Profile statuses distinguish
"not configured/not found" from "empty"; (e) `govibe graph index` builds and caches the app binary.
