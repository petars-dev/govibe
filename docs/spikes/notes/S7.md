# S7 — Module rename `petars-dev/govibe` -> `github.com/petars-dev/govibe`

Scratch copy: `spikes/s7` (from `spikes/base`). Script: `spikes/results/s7-rename.sh` (reusable for Phase 2 T2.1).
Usage: `s7-rename.sh [ROOT] [OLD] [NEW]`, defaults are the two paths above. Run from anywhere; it `cd`s to ROOT.

## Count
`grep` for the old path (as a path, not preceded by `github.com/`) finds **39** files in the copy; **38** after
excluding the spec itself. The spec's "38 tracked files" is exactly right:
- 37 `.go` files (codegraph 17, controllers 10, devmcp 5, cmd/govibe 3, routes 1, main.go 1),
- `go.mod`,
- (+ `docs/specs/SPEC_FRAMEWORK_EXTRACTION.md`, which *describes* the rename and must keep the old path in its prose.)
No README, SKILL.md, Makefile, `.air.toml`, workflow, docs, template, golden or `go.sum` contains the old path.
(The first count showed a 39th hit, `.idea/workspace.xml`: an untracked, git-ignored IDE file that rsync copied. The
script now prefers `git ls-files` inside a repo and excludes `.idea/`, `.vscode/`, `.git/`, `docs/graph/*.bolt`.)

Pre-existing `github.com/petars-dev/govibe` references: only in the spec itself (5 lines). They are not corrupted:
the pattern is `(?<![A-Za-z0-9._/-])petars-dev/govibe(?![A-Za-z0-9_-])`, i.e. a reference preceded by `github.com/`
(or any host/path character) or followed by a name character (`petars-dev/govibe-extra`) is never matched. Verified:
0 occurrences of `github.com/github.com`, and a second run reports "nothing to rewrite" (idempotent).

## Run
`bash s7-rename.sh .` -> "rewrote 38 files", "ok: module github.com/petars-dev/govibe". Line delta: 89 lines changed on
each side. Only 6 files differ from a pure `sed` substitution, all because the script then runs `gofmt -w` on the
changed files that were gofmt-clean before (so the rename adds no unrelated formatting noise):
- import blocks re-sort (`"net/http"` now sorts after `"github.com/petars-dev/govibe/..."`): `controllers/{api,hello,home}.go`,
  `routes/routes.go` (4 diff lines each, no logic);
- map-literal value re-alignment because one key got 11 characters longer:
  `business/services/codegraph/agent_repo_test.go` (30 lines), `layers_test.go` (6 lines).
Two files were already gofmt-unclean before the rename (`cmd/govibe/cmd_generate.go`, `cmd/govibe/root.go`; spaces
instead of tabs, unsorted imports); they contain no module path, are not touched, and are still reported by
`gofmt -l` (pre-existing; fix in a separate commit, not in the rename).

## Things checked on purpose
- **`testdata/fixture` keeps its own module name** (`example.com/fixture`, a nested module with its own `go.mod`,
  excluded from `./...`). It never mentions the framework path, none of the 9 goldens contains the module path, so it
  needs no change now. Phase 3 T3.11 rebuilds it as an app that depends on a stub framework; the stub should get a
  neutral path (e.g. `example.com/stubgovibe`), not `github.com/petars-dev/govibe`, so the fixture cannot accidentally
  resolve to the real module.
- **Symbol-name strings that embed the module path**: `layers_test.go:502-504` holds `runtime.FuncForPC`-style names
  (`petars-dev/govibe/controllers.Home`, `...(*Server).Handle-fm`) as parser inputs. After the rename they read
  `github.com/petars-dev/govibe/controllers.Home`, a path whose *first* segment contains a dot; the symbol parser
  handles it (the test passes). Worth keeping: this is the same shape S2 sees for framework handlers.
- `agent_repo_test.go:118` resolves the ref `github.com/petars-dev/govibe/controllers` -> `pkg:controllers`, i.e.
  the indexer derives the module prefix from `go.mod`, not from a constant. The rename needed no indexer code change.
- **Derived data not exercised**: `docs/graph/indexes.bolt` (git-ignored) may hold node data keyed by the old import
  path; the base copy has none. It is rebuilt on every boot, so T2.1 should delete `docs/graph/*.bolt` (or rely on the
  rebuild) rather than rewrite it; the script deliberately skips `.bolt`.
- `docs/graph/baseline.json` has no module path (finding IDs are repo-relative), so it needs no change.
- External effects not covered here: `go.mod`'s module line is the only place `go list -m` reads; GitHub already hosts
  the repo at `github.com/petars-dev/govibe`, so no remote change is needed.

## Consequence for the design
T2.1 is a safe, mechanical, one-command step: 38 files, formatting-only side effects, no golden change, build/vet/tests
unchanged. No spec change is needed except to say the count is 38 **excluding** this spec, and that the rename script
(kept at `spikes/results/s7-rename.sh`, to be committed as `scripts/rename-module.sh` or run once and dropped)
skips the spec on purpose. Recommendations for Phase 2: do the rename as its own commit (no moves in it), run the
script, review `git diff --stat` (expect ~38 files / ~89 lines each side plus the gofmt re-sorts), regenerate nothing,
delete `docs/graph/*.bolt` before the first boot, and fix the two pre-existing gofmt-unclean files in a separate
commit so the rename diff stays pure. Do the rename *before* the `git mv` moves of T2.2 (one rename of paths, then one
of locations) so the goldens-identical proof applies to each step separately.
