# S5 — Embed hand-over

Scratch: `spikes/app` (`example.com/shop`, root `main.go` embeds `env.yml`; `storage/migrations` embeds `sql/*.sql`;
`assets` embeds `static/**`), framework prototype in `spikes/fw`: `govibe.App{Config, Migrations, Assets fs.FS}`,
`internal/kernel.Build` (one boot path), `config.LoadLayered` + `config/defaults.yml`, `internal/migrate`, `govibetest.Boot`.
Every process was started under `env -i` (no database vars); tests under `env -i` with only PATH, HOME, GOCACHE, GOMODCACHE.

## Results
| Item | Result |
| --- | --- |
| `//go:embed env.yml` in the app's root `main.go` into an `embed.FS`, handed as `App.Config` | Works. The FS root holds `env.yml`; the loader reads `fs.ReadFile(app, "env.yml")`. `go run`, the built binary, and `go test` of package `main` all see it. |
| `newApp()` booted from `main_test.go` via `govibetest.Boot` | Works: `/hello` returns the value from the embedded `env.yml`, `/api/hello` the JSON, framework defaults visible (`scheduler.timezone` = `UTC`). |
| Migrations and assets as `fs.FS` | Works. `fs.ReadDir(newApp().Migrations, "sql")` lists the file; assets served from `http.FileServerFS(app.Assets)` at `/assets/static/home.css`. |
| goose over the handed-over FS | Works with the **instance** API: `goose.NewProvider(dialect, db, fs.Sub(migrations, "sql"))`, `ListSources()` returns `1:0001_init.sql`, `2:0002_more.sql`; **no connection is made** (`sql.Open` does not dial, the provider only needs the handle). An empty dialect is an error; the repo's global `goose.SetBaseFS`/`SetDialect` API still works but is process-wide state. 4 tests in `internal/migrate`. |

| Dev disk override for `./assets` | Works, and it is **cwd-dependent** (below). |

`routes/routes_test.go` (1), all passing.

## Dev disk override: what actually happens
Kernel rule used: serve `./assets` from disk when `env` is `local`/`dev` **and** the directory exists relative to the **process cwd**; else embedded `App.Assets`.
| Run | boot note | |
| --- | --- | --- |
| binary, cwd = app root, `APP_ENV=dev` | `assets: disk assets` | served from the directory |
| same binary, cwd = `/tmp`, `APP_ENV=dev` | `assets: embedded` | **silently falls back to the embedded copy** |
| binary, cwd = app root, `APP_ENV=prod` | `assets: embedded` | correct |
| `go run .` from the app root | `assets: disk assets` | |
| `go test` in package `main` (cwd = package dir = app root) | `assets: disk assets` | |
| `go test` in `routes/` (cwd = `routes/`) | none: that test's `App` has no `Assets` and `./assets` does not exist there (not run with assets) | |
Same behavior as today (`routes.NewRouter` uses a bare `"assets"`), but with the app in its own module and `air` running the built binary from `tmp/`,
cwd stops being a safe anchor. Anchor on the app root instead (`GOVIBE_ROOT`, else the nearest directory with `govibe.yml`/`go.mod`, which the spec already
uses for the graph store). The boot log line "assets: disk <abs path>" is what made this visible; keep it.
The prototype did not port `DevNoCache` (no `Cache-Control` on disk assets): it must move to `web`/kernel with the rest.

## Awkward or surprising
1. **Only the root package can call `newApp()`**: `main` is not importable, so tests of `routes/`, `controllers/` build their own `App` with a `fstest.MapFS` standing in for
   `env.yml` (worked, see `routes/routes_test.go`). Suggest scaffolding a tiny `internal`-free `app` helper only if this proves annoying; the spec's `main_test.go` boot is fine.
2. **The `sql` directory name is a contract between the app's embed pattern and the runner** (`//go:embed sql/*.sql` plus `migrate.Dir = "sql"`).
   `fs.Sub` of a missing dir does not error by itself; goose then reports no migrations. `doctor` should check the pattern (the spec's "missing embeds" check covers it).
3. **`${ENV:default}` coercion is carried over "exactly as today" and it corrupts string-like defaults:**
   `${V:1.10}` -> `1.1` (float64), `${V:00123}` -> `123` (int64), `${V:12345678901234567890}` -> `1.2345678901234567e+19`, `yes` stays a string; **quoting
   in the YAML does not help** (`"${V:1.10}"` -> `1.1`). A version string or zip code in `env.yml` changes silently. Cheap fix that stays compatible:
   leave a quoted scalar as a string (nobody quotes today), and document it. Not a blocker; worth a test in T1.1.
4. `app/env.yml` overriding `server.port` changes which env var sets it (`SHOP_PORT`, not `PORT`). The scaffold should **not** override framework placeholders (the Makefile and
   `.air.toml` pass `PORT`); app files add keys, they do not re-bind framework ones. Layering semantics are as the spec says (app wins), so this is a convention to state.
5. The test boot must not inherit ambient secrets: `govibetest.Boot` builds with no database (`OpenDB: false`), and any test that opts into a database should
   neutralize `MARIADB_DSN` unless it sets its own. (This shell exports the real local DSN. No spike process was started with it in its environment: every boot ran under `env -i`, and the test runs read only `GOVIBE_TEST_MARIADB_DSN`, which was unset.)

## Consequence for the design
The spec's hand-over holds exactly as drawn: `env.yml` embedded from the root `main.go`, migrations/assets as `fs.FS`, defaults beneath, one boot path for `Main`, `serve`
and tests. Changes to carry: (a) goose through the **Provider API** (`internal/migrate` instance-based, dialect a required type) instead of the global `SetBaseFS`/`SetDialect`
(T1.2); (b) resolve the dev assets directory against the app root, not cwd, and log the resolved absolute path; (c) quoted placeholders stay strings (T1.1 test); (d) `govibetest`
disables the database by default and says so.
