# S3 — Calls layer across modules

Driver: `spikes/fw/cmd/spikecalls` (built to `spikes/spikecalls`): `packages.Load` exactly as `layer_calls.go` does
(`NeedName|NeedFiles|NeedCompiledGoFiles|NeedImports|NeedTypes|NeedSyntax|NeedTypesInfo`, `Tests:false`, pattern `./...`,
`Dir` = the app) plus `NeedModule` and, for the tagged runs, `BuildFlags: ["-tags=govibe_dev"]` (the current layer has no
`BuildFlags`). App = `spikes/app` (9 packages, `replace => ../fw`), and `spikes/app-mod` for the module-cache variant.
Run under `env -i` with only PATH, HOME, GOCACHE, GOMODCACHE. Go 1.26.5, darwin/arm64. The tagged variant has a tag-only
app file (`routes/dev_on.go`, with a `!govibe_dev` twin `dev_off.go`) and the framework's stand-in dev mount
(`internal/kernel/dev_mount.go`, tagged, importing `codegraph`; the real dev stack is S1's).

## Time and size (fresh `GOCACHE` for the cold runs; the machine was under load from sibling forks)
| | cold `GOCACHE` | warm | packages in the closure | packages with syntax + types | GOCACHE after |
| --- | --- | --- | --- | --- | --- |
| default flags | 8.5 s | 0.20 s, 0.19 s | 222 | 10 | 130 MB |
| `-tags govibe_dev` | 13.0 s | 0.25 s, 0.22 s | 289 | 10 | 194 MB |
| module-cache app (no replace), default | 7.4 s | n/m | 222 | 10 | n/m |

`roots` (what `./...` matches) = 9 app packages in both. Only the app's own packages carry syntax; everything it imports,
framework included, comes from export data (`go list -export`), which is why cold is the cost of compiling the closure
once and warm is a fraction of a second. The tagged closure is larger (+67 packages here, because the stand-in dev mount
pulls `codegraph`; with the real dev stack it grows to S1's 440). The existing layer's `callsTimeout` of 3 minutes is ample.

## Does the framework in another module change anything?
No. `go/packages` loads the app with the framework as an ordinary dependency, with a `replace` and without one. The framework's
packages are imported as stubs with export data and the type checker resolves calls into them normally.

### Surprises
1. **`p.Imports[path].Module` is empty for packages the app does not import directly** (`config`, `logrus`: reached through a
   field's type). Module info must come from an index over the whole closure (`packages.Visit`), which has it for all 222/289.
2. **Type aliases do not hide `internal/`.** `govibe.Runtime = kernel.Runtime` is public, but a method *declared on* it is
   reported in `internal/kernel` (`(*...internal/kernel.Runtime).Env`). Any method on `Runtime` (or any alias to an internal type) would
   put `internal/kernel` into every app's call edges. Prefer fields over methods on aliased types, or collapse by module
   (below).
3. **Calls the layer cannot see** are unchanged and now matter more: calls through function values (`govibe.RunFunc` is a
   func type; `c.Run(ctx, ...)` is invisible), through `http.Handler`, and from package initializers. The framework's seams
   (`App.Routes`, `Command.Run`) are exactly such values, so the edge "main -> routes.Register" is not in the call graph; it is in the
   routes layer (`routes.Register` is the `Routes` field value, found by `FuncForPC`, S2/S6).
4. **A tag-only file is invisible without the tag, and vice versa.** The code layer is AST-based and parses *all* files
   (same-name functions in differently tagged files get `#2` IDs, `code.go:876`), so `routes.devRoutes` exists in the graph twice.
   Without `-tags govibe_dev` the type-checker never sees `dev_on.go`, so its function has **no call edges, silently**; with the tag the
   `dev_off.go` twin has none (it is empty). Today's layer would say "no calls" for the tagged file. T3.7 must load with the tag (as
   the spec says) and should say so in the layer's note ("type-checked with tags: govibe_dev").

## Proposed bound for edges into the framework
Today `callResolver.call` drops every callee that is not a node of the code index, so *nothing* outside the app is recorded;
the spike measured that 32 of the 45 call sites (default build) are of that kind, so the bound decides how much the graph grows.
1. **Stop at the first package outside the app module; never descend.** The type-checker already does (no syntax for dependencies).
2. **Record an external leaf only for the framework's public packages** (`govibe`, `config`, `web`, `govibetest`): function-level,
   `ext:<module>/<pkg>.<Recv.Name>` with `module` and `version` from the `Package.Module` index, `origin=framework`. That is bounded by the
   public API (four packages), and it is what `framework.import`, "uses framework: web, config", and a future "who calls `web.JSON`" need.
3. **Everything that resolves into the framework's `internal/` collapses to the module-level leaf** (`ext:github.com/petars-dev/govibe`,
   flagged `internal`), so aliases (surprise 2) cannot leak internals or make `internal/` part of any contract.
4. **Third-party dependencies: package granularity**, one leaf per package with module and version (`chi/v5`, `sqlx`, `logrus`), so
   "which stores reach `sqlx`" is answerable without a node per method. **The standard library is not recorded** (9 of 45 call
   sites here; `fmt`, `net/http` add noise and no architectural information).
5. Interface calls into external interfaces stay unexpanded (the layer already does that for interfaces it does not declare), recorded as one edge to the
   interface's package leaf.
Edges stay `calls`, annotated with `origin`; the scope filter (S9) then drops `framework` and `dependency` leaves in the app view, so the default
graph is unchanged and `scope=all` shows them.

## Consequence for the design
The spec's plan holds: **T3.7 is feasible as written** ("tag-aware load, bounded edges into the framework"). Cost with the real dev stack:
cold 13 s on a loaded machine, warm about a quarter of a second for a 9-package app (the layer's own comment says about a second for this repository);
the layer stays opt-in. Changes to carry into the spec: (a) build the module index from `packages.Visit`, not from `Imports`;
(b) add `BuildFlags` from the inspect document's `build.tags` (the app binary says what it was built with, so a `go tool govibe graph index` run
need not guess; default to `govibe_dev`); (c) the bound above, including the rule that public `Runtime`/alias targets must not carry methods
declared in `internal/`; (d) the calls layer note must state the tags it was loaded with.
