# S2 — Cross-module routes

Scratch: `spikes/fw` (copy of `base`, with the prototype `govibe.App`/`Main`/`Runtime` added; see S5/S6),
`spikes/app` (`module example.com/shop`, `require petars-dev/govibe v0.0.0` + `replace => ../fw`),
`spikes/app-mod` + `spikes/fw-mod` + `spikes/proxy` (the same app against the framework renamed to
`github.com/petars-dev/govibe` and served from a local `file://` GOPROXY, so it resolves from a module cache, no `replace`).
Go 1.26.5 darwin/arm64. Four builds of the same app: **replace**, **replace + `-trimpath`**, **module cache**,
**module cache + `-trimpath`**. Regenerate the module-cache variant with `spikes/refresh_mod.sh`.

Evidence below is the output of `env -i ./shop-<variant> inspect --json` (the handler `Name()`/`FileLine` the way
`layer_routes.go` records them); long paths shortened (`$SPIKES`, `$GOMODCACHE`, `$GOROOT`).

## 0. Does a hostless module path work?
Yes, with `replace`. `require petars-dev/govibe v0.0.0` + `replace petars-dev/govibe => ../fw`: `go mod tidy`,
`go build`, `go list -m`, `go/packages` and `go test` all work. (Without a `replace` it cannot be fetched at all,
which is constraint 10 of the spec; S7 covers the rename.) Nothing needed the rename for this spike except the
module-cache variant, which has to be fetchable.

### Rules the data supports
1. **The file path is the truth, the symbol is not.** When the compiler inlines a factory into its caller, the closure
   is *named after the caller*: `web.Health("from-app")` called from `routes.Register` reports
   `example.com/shop/routes.Register.Health.func3` (an **app** symbol) at `.../web/web.go:22` (a **framework** file);
   `http.StripPrefix` mounted by the kernel reports `petars-dev/govibe/internal/kernel.Build.StripPrefix.func3` at
   `net/http/server.go`. Classifying by symbol prefix mislabels both. (The old `externalSymbol` already special-cased
   the app-module case for this reason.)
2. **The path spelling depends on the build, in four ways:** replace (absolute path of the replace target, e.g.
   `$SPIKES/fw/web/web.go`); module cache (`$GOMODCACHE/<mod>@<ver>/...`, and `GOMODCACHE` can be anywhere, it only
   usually contains `/pkg/mod/`); `-trimpath` main module (`<module>/<rel>`, no version: `example.com/shop/controllers/home.go`);
   `-trimpath` dependency (`<mod>@<ver>/<rel>`, version taken from `require`: `petars-dev/govibe@v0.0.0/...`). Stdlib:
   `$GOROOT/src/...` or `net/http/server.go` under `-trimpath`.
3. **`debug.ReadBuildInfo()` records a local replace as `=> ../fw (devel)`**: the path *as written in go.mod*
   (relative!) and Version `(devel)`, not empty. Resolving it needs the app's compile-time root.
4. `<autogenerated>:1` method-value wrappers have no source at all; only the symbol is usable, and it is not
   inlined into anything, so symbol-based classification is correct for them.

## 2. How the existing indexer classifies these today
`layer_routes.go`: `resolveFunc` maps `File:Line` onto the code index through `sourceRel`, which needs `buildRoot()`.
**`buildRoot()` derives the app's compile root from where the indexer package itself was compiled**
(`runtime.Caller` + `reflect.TypeOf(world{}).PkgPath()` minus `ci.module`), which only works while the indexer and the
indexed project are the same module. Once the indexer lives in the framework module and the project is the app, it
returns `""` and **every handler except `-fm` method values is unresolved** (measured: 5 of the 6 app handlers; the sixth
resolves by symbol). Library/framework handlers fall to `externalSymbol` and get a string attribute `handler`, no node.
Nothing is classified by origin.

## 3. The minimal change that works (in `spikes/fw` only)
Passing: all four builds produce the same classification (diff of normalized output: 0 lines), 17/17 routes, 0 unknown.
1. **Build-root hint** (`Options.BuildRoot`): the app binary reports where `App.Routes` was compiled
   (`FuncForPC(App.Routes)` symbol + file, in the inspect document as `app.root_hint`); the root is the file's dir minus the
   symbol's package path relative to the module (`routes/routes.go` + `example.com/shop/routes` -> `<root>/`; under
   `-trimpath` this is `example.com/shop/`). Edge case: if `Routes` lives in `package main`, the root is the file's dir.
2. **Module table** (`Options.Modules`, `Options.FrameworkModule`): `build.modules` in the inspect document is
   `debug.ReadBuildInfo().Deps` with local-replace dirs; the indexer matches a file by `<mod>@<ver>/` anywhere in the
   path, by prefix under `-trimpath`, or by the replace dir (made absolute against the build root). That removes the
   `/pkg/mod/` guess in `externalPackage`, which breaks with a custom `GOMODCACHE`, and the `@version` wart under
   `-trimpath` (`petars-dev/govibe@v0.0.0/web.Health`).
3. **`classify(file) -> origin app | framework | dependency | stdlib | unknown`** (162 lines, `origin.go`): app root first,
   then the module table, then stdlib heuristics; symbol only for source-less `-fm` wrappers.
4. **External nodes**: a handler outside the app gets `kind:external` (`ext:<pkg>.<Recv.Name>`, attrs `origin`, `module`)
   and a `handled_by` edge, instead of an unlinked string. Name = the declared symbol when it is in the file's package,
   else the last element (the inlined callee): `web.Static.ServeHTTP`, `web.(*Version).Handle`, `web.Health`,
   `net/http.StripPrefix`.
5. **Route origin = who registered it, not whose function serves it.** The kernel snapshots the route table before
   it calls `App.Routes` (`FrameworkRoutes`), so each route is `mounted_by: framework|app`. Needed because the two
   signals disagree both ways: `/assets/*` is a framework route served by a **stdlib** handler, `/files/*` is an **app** route
   served by a stdlib handler, `/fw/ping` is an **app** route served by a **framework** handler. A pure
   "handler outside the app root = framework" rule (spec, T3.2) would hide `/files/*` and `/fw/ping` in the app view.
   The graph keeps both: route `origin` (= mounted_by) and `handler_origin`.
6. `docs.route_undocumented` skips `origin=framework` routes. Without that, a fresh app gets 8+ findings for
   `/_govibe/*` and `/assets/*`, and A1 ("zero findings at any severity") cannot hold. With it, only the app's own routes
   are judged (including `/fw/ping`, which the app chose to mount).

Cost: codegraph diff +53/-88 lines (most of the removal is the chi walk moving to `internal/routeinfo`) plus the
162-line `origin.go`. `go vet` is clean.

### Test impact (measured: `go test ./business/services/codegraph/`, refactor-only vs additions on)
The additions were gated behind an env var for one run, so the two parts could be separated:
- **Refactor only** (`runtimeRoute`/`handlerRef` become aliases of `internal/routeinfo` types, the chi walk moves there,
  no new attributes): everything passes except `TestRepoInvariants` and `TestWholeGraphInvariants`, which assert facts about
  this repo's root `package main` (`func:..main`, "root package name = main", root imports `routes`). Those two fail only
  because the prototype replaced the root `main.go` with `package govibe` in the copy; the aliasing itself breaks nothing.
  A pure move is therefore as safe as the spec's Phase 2 rule needs.
- **Additions on:** 11 tests fail, the two above plus nine that react to the new quads: the schema-completeness tests (`origin`,
  `handler_origin`, `module`, `kind:external` have no description), the routes golden (new quads), three "handled_by joins a route to a
  func" invariants, and the fixture/report/context tests that assert a library handler is a plain string. Those need the Phase 3
  golden review the spec already plans (T3.11).
- One test, `TestRoutesLayerOnARealChiRouter` (a live in-process router), stops failing once classification depends on the module
  table: with no `Options.Modules` a library handler is `unknown` and gets no external node. **Live (in-process) mode must therefore fill
  `Modules`, `FrameworkModule` and `BuildRoot` itself** (from `debug.ReadBuildInfo` and `App.Routes`); the spike only implemented the
  offline path.

## Consequence for the design
- The plan holds: handlers in another module are **resolvable** and can be **external nodes**. S2's own fallback
  ("external nodes") is the primary path, not the fallback, for framework handlers.
- **Spec changes:** (a) T3.2 "routes classified by handler location" -> classify by **registration site** (`mounted_by`,
  snapshot before `App.Routes`) plus handler origin from **file + module table**; never by symbol prefix. (b) `buildRoot`
  must stop depending on where the indexer was compiled: add the root hint to `inspect --json` and to `Deps`
  (live mode derives it the same way from `App.Routes`). (c) `inspect --json` carries `build.modules`
  (ReadBuildInfo deps with replace dirs), `build.trimpath`, `build.tags`; the document must **not** carry symbol-derived
  origins. (d) the chi walk and `FuncForPC` code must live in a light package (`internal/routeinfo`, chi+reflect only) because
  the app binary needs it for `inspect --json` and must not link cayley (A2). In the spec's layout that is a new
  `internal/routeinfo` (or part of `internal/kernel`), not `internal/codegraph`.
- Reserved prefixes: the kernel's registration-time snapshot also gives the "app registered something under `/dev/` or
  `/_govibe/`" check for free (compare the post-`Routes` table against the reserved prefixes; the spike left it a stub).
